# 2026-10-28

## 新增 CI（GitHub Actions）

`.github/workflows/ci.yml`：单 job，跑 `macos-latest`，原生 darwin/arm64（用户确认只支持 Apple Silicon）。

- 所有触发：`make build` + `make check`
- 仅 push 到 main：`make pkg` + `make verify-pkg` + 上传 PKG 制品（名带短 SHA）
- **刻意不再单独上传裸二进制制品**：它会把人推进 dev 路径（手工 token/agent/server，
  且非 root 下 PF、重启、launchd 全残废）。只有安装包才是真实使用形态。
- 为什么是单 job：build/test 两个并行 job 各自跑一遍 npm ci + 前端构建，
  macOS 分钟数按 Linux 倍数计费，拆开等于把最贵的一段烧两遍。

## 设计审视（grill-me）

用户质疑「跑三个命令才能用」不合常理——质疑成立，且病因比表面更深：

- `postinstall` **已经**自动建 `_macpanel` 账户/组、自动生成 IPC 令牌、自动
  `launchctl bootstrap` 两个服务。**正式安装路径是 0 命令。** 三个命令只属于源码 dev 路径。
- 所以真实结论是 **CI 交付了错误的产物**（裸二进制），把人逼进 dev 体验。修复 = 出 PKG。
- dev 路径保留手工 token：**不做自动自举**。理由不是保守，是竞态——agent/server
  各自补令牌会生成不同凭据，IPC 认证变成偶发失败（比明确报错更难查）。
  真正该修的是 `config.LoadToken` 失败时那句没有指向性的报错（未做）。

## 根权限的结论（用户认可，暂不改）

PF 写规则 / 定时重启 / launchd 系统域服务**必须 root，且与「是否需要注销后常驻」无关**。
用户原诉求「登录后管理」并不能省掉 root——这两条轴不相关。
后续若介意常驻，正解是 launchd socket activation，而非去掉 root。

## 实机首装（本机 zhanghandeMac-mini）暴露的两个缺陷

历史前提：开发机无 sudo，**preinstall/postinstall 从未真跑过**，M5 只有静态校验。

### 1. 卸载后再重装，面板依旧起不来（plist 消失）

现象：`/Library/LaunchDaemons/` 里没有任何 `com.macpanel.*.plist`，无进程、7788 无监听。

排查三件套（以后照用）：
- `pkgutil --files com.macpanel` —— 收据说**装了**（含两个 plist）
- `ls /Library/LaunchDaemons/` —— 磁盘上**没有**
- `lsbom -pf <展开的 pkg>/component.pkg/Bom` —— **包里确实有** → 排除打包缺文件

根因：两次安装版本号都是 `0.1.0`，触发 macOS **receipt-based obsoleting**，
安装收尾时（观察到 LaunchDaemons 目录 ctime 比安装完成晚 1 秒）把 payload 文件删掉；
而 `uninstall.sh` **从不清除收据**，于是「卸载→重装」永远仍是同版本覆盖，必然复现。

修复：
- 版本号强制递增：`MACPANEL_PKG_VERSION`（CI 传 run_number）> git tag > `0.1.<提交计数>`
- `uninstall.sh` 开头就 `pkgutil --forget com.macpanel`（放最前：中断也能留下干净状态）

### 2. 升级前备份只增不减

`preinstall` 用 `head -n -"${KEEP}"`：负行数是 GNU 专有语法，macOS BSD head 报
`illegal line count -- -5`，整段静默失败。改用 `sort -r | tail -n +"$((KEEP + 1))"`。

## 本机环境补充

- 本会话中 **grep / Grep 工具多次对明明有内容的文件返回空**（`internal/config`、`build-pkg.sh`、
  `uninstall.sh`、`lsbom -f`），同一命令换 `cat`/`Read`/`sed -n` 就有内容。
  **不能把空结果当成「不存在」的证据**，必须再读一遍。
- `lsbom -pf` 给路径，`-f` 给「路径/八进制mode/uid/gid/size」。
- `pkgutil --expand-full` 后 component.pkg/Bom 可直接 `lsbom` 验 payload 内容。

## 局域网 / easytier 访问改造

需求：让面板能通过 easytier 的 `10.10.10.10` 访问（原设计只允许本机）。
用户拍板：**监听 `0.0.0.0:7788`**、局域网访问**强制登录**、配置**做成正式功能**。

### 机制本来就有，坑在「配置放在哪」

`MACPANEL_LISTEN_ADDR` + `MACPANEL_ALLOW_REMOTE` 早就支持，但生产环境这两个值写在
launchd plist 里，而 `postinstall` 每次按模板重写 plist —— 手改必丢。所以真正缺的是
**一个升级不会覆盖的配置文件**，以及改它的命令。

### 落地方案

| 层 | 内容 |
| --- | --- |
| `internal/config/file.go` | `server.conf` 的解析/写入；未知键与语法错误**报错而不是忽略** |
| `config.Load(LoadOptions)` | 优先级 `环境变量 > server.conf > 默认值` |
| `macpanel config show/set/unset` | `set listen` 非回环时自动置 `allow_remote`，写盘前跑真实校验 |
| plist | **删掉** `MACPANEL_LISTEN_ADDR`（env 优先级更高，留着等于配置文件永远失效） |
| postinstall | 文件不存在才创建（`root:_macpanel 0640`，权限每次强制校正） |

### 顺手修的两个真 bug

1. `NormalizedListenAddr()` 把 `":7788"` 改写成 `127.0.0.1:7788`：校验阶段按
   「所有网卡」放行，监听却退化成只看回环 —— 两边判断不一致。
2. `hostGuard` wildcard 分支原来「任意合法主机名都放行」，等于监听 `0.0.0.0` 时
   放弃 DNS rebinding 防护。改为只认 **IP 字面量 + localhost**；域名必须显式
   `public_hosts`。（`evil.com` 这样的 Host 412→421 已用测试固定）

### 引导路径不能断

初始密码只允许回环设置（`auth_handlers.go`）。绑 `0.0.0.0` 时回环仍在监听，所以
没死锁；但绑具体 IP（`10.10.10.10:7788`）会失去回环入口，此时若没设密码就进不去。
回退靠 CLI（本机 `sudo macpanel config set listen 127.0.0.1:7788`），不需要面板可访问。

### 本机验证事实

- `curl http://192.168.1.2:7799/...` 通、`/api/v1/system/overview` 返回 403（缺
  `X-HLM-Request`），行为符合「强制登录」。
- **`curl http://10.10.10.10:7799` 从本机自己访问会超时**：TCP 能握手，HTTP 无响应。
  用裸 `nc -l 10.10.10.10` 同样收不到数据 —— 说明包被路由进 utun2 发给 easytier
  对端，与本应用无关。**验证 easytier 通路必须用另一台设备**，别拿本机 curl 自己的
  隧道地址当结论。
