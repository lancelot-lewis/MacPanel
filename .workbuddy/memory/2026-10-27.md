# 2026-10-27

## MacPanel — 把名字统一成 MacPanel（全量改名）

用户指出「项目已经改名叫 macpanel 了」。核实后发现：**外壳早就改了、里面没跟上**——
GitHub remote 与 go.mod 从首提交起就是 `lancelot-lewis/MacPanel`，
但 114 个文件里仍是 `homelab-manager` / `HomeLabManager` / `com.homelab.manager.*` / `_homelab`。
以前没注意到这一点，是这轮的疏漏。

用户确认范围 = 全部统一，展示名 = MacPanel。

### 改名映射

| 旧 | 新 |
| --- | --- |
| `homelab-manager` | `macpanel`（二进制；`cmd/homelab-manager/` → `cmd/macpanel/`） |
| `HomeLabManager` | `MacPanel`（安装包名、目录名） |
| `com.homelab.manager.*` | `com.macpanel.*`（launchd label、PF anchor） |
| `_homelab` | `_macpanel`（服务账户） |
| `HLM_*` | `MACPANEL_*`（环境变量前缀，157 处） |
| `homelab.db` | `macpanel.db` |
| `HomeLab Manager` | `MacPanel`（展示名） |

共 114 个文件 437 处 + 第二轮 7 处 + `git mv` 目录与两个 plist 文件名。

### 保留不动的三类（别当成遗漏去「修」）

1. `com.homelab.ipv6` —— 本机第三方服务的**真实名字**，不是本项目创建的。
   改名后本项目用 `com.macpanel.*`，两者不再容易混淆，反而更安全。
2. `homelab.example.com` —— config 注释与测试里的示例域名。
3. 「家庭实验室 / HomeLab」作为**场景词**仍保留在 PLAN 里。

### 批量替换踩到的两个坑

- **场景词被当成产品名替换**：「无人值守的 HomeLab 会失去管理入口」→
  「无人值守的 MacPanel…」语义从"场景"变成"产品"，读起来是错的。
  机器替换后必须逐个复核语义，不能只看 grep 计数归零。
- **测试数据歪打正着**：`TestValidateRejectsForeignLabel` 里有一条
  `homelab.manager.task.1`（漏写 `com.` 前缀），本意是「拼写不完整的自家 label 也要拒绝」。
  改名后它变成合法的 `com.macpanel.task.1`，用例失效——不是新 bug，是原用例靠拼写错误成立。
  改用 `com.homelab.ipv6`（真实的第三方服务）与 `macpanel.task.1`，
  并补了反向用例 `TestValidateAcceptsOwnLabel`（防止校验过严导致自家任务装不上）。

### 顺手加固

`launchd.Spec.Validate` 里校验可执行文件原用 `strings.Contains(prog, "macpanel")`，
会放行 `/tmp/evil-macpanel` 这类路径。改为 `filepath.Base(prog) != binaryName`，
并把二进制名抽成 `binaryName` 常量（与 `LabelPrefix` 并列，方便以后改名）。
